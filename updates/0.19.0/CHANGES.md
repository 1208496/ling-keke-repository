# 香火成神系统 0.19.0 改了什么

卡面 0.19.0，Schema 2.4.0。旧存档（2.3.0）在切换聊天时按固定的一条边迁移，只补默认值，不动余额、信徒和旧任务。

## 一、状态栏多了「己身」页

- 页签从 5 个变 6 个：此刻、**己身**、权柄、因果、神格、地图。窄屏排成两行三个。
- 系统商城、背包、祈愿簿、神力账本四块从「此刻」和「权柄」搬到己身页，从上到下同一种盒子。
- 祈愿簿离开了默认页，所以「己身」上带一个金色角标，写着还有几个人的祈愿在等。
- 刷新页面、来回切页签、重 draw 状态栏之后，展开状态和当前页签都还在（`data-key`、`data-tab` 没改）。

## 二、系统商城改成弹窗

- 己身页的商城只剩：标题、可用神力、眼下处境、「打开商城」按钮。
- 弹窗里四个页签：今日货架、跨界货架、涩涩货架、信徒权能。方向键切换，Esc 关闭，关掉焦点回到按钮。
- 卡片统一：名称 + 类别小牌 + 状态 + 说明 + 效果小字 + 底部按钮。手机宽度下卡片单列、按钮占满一整行。
- **买完不关弹窗**：确认框 → 扣费 → 余额、限购数、卡片按钮当场刷新，停在当前页签；失败写在弹窗底部的错误行里。
- 生成中点按钮照旧被拒（「正文正在生成，请结束后再操作」），错误照样显示在弹窗里。
- 状态栏重绘时，开着的弹窗跟着刷新。

## 三、涩涩货架

- 六件：迷魂药、催情散、合欢酒、龙虎丹、演化玉势／硅胶鸡巴、演化缅铃／跳蛋，三个世界各有自己的叫法，价格固定不随阶段涨。
- 单独放 `rules.goods.lewd`，**没有**塞进今日货架，所以不会混进处境匹配和每天的抽取。
- 跟着祈愿簿的「涩的祈愿」开关走：关掉时页签还在，只显示一行字，买也买不了。
- **限时操控**：两件演化的器具买下后用一个「演化」字段计时，60 剧情分钟后自动化回神力；背包里的「神力演化中」卡片可以「轻一点 / 加大 / 换个花样」（往输入框填一句）和「收回」。
- 生效那一楼重 roll 不会多建记录；到期由结算清理；玩家楼层不登记。

## 四、信徒信仰度

- 只有具名信徒有信仰度，0–100。群体和匿名人数没有。
- 分段：普通 0–59（到 60 升核心）、核心 60–99（到 100 升狂热）、狂热就是 MAX。
- **AI 只报事实**：提交 `{"类型":"信仰","人物ID":"…","事由":"拯救","程度":"重"}`，事由八个（回应、显灵、拯救、应愿、亲近、赐福、冷落、失望），程度轻中重。分数由脚本查表：普通 ×1、核心 ×0.5（向上取整），扣分不受上限。
- **每人每日上限**：普通最多 +30、核心最多 +15，跨日清零。
- **升级只由脚本做**：普通到 60 自动升核心、核心到 100 自动升狂热，升级后下一轮正文收到演出提示（谁升了、写什么），演过就消失。
- **AI 不能再直接把人写成核心或狂热**：会被改回原等级，人数跟着退回，回一句「具名信徒要靠信仰度升级」。入信（→普通）和脱离照旧可以写。
- 入信那一刻信仰度是 10。旧存档里的具名信徒按普通 20、核心 60、狂热 100 补。
- 狂热要石像期才开放：泥像期的核心停在 99，卡片上写「信仰 99 · 狂热需石像期」。
- **私密状态**只有狂热信徒有（身体、欲念、秘密），升级那一轮脚本先给一个空的，从下一轮起 AI 才写。核心及以下写了会被删。
- 三处人物卡都带信仰度：因果页的紧凑卡、此刻页的在场人物、详细资料；详细资料多一段「当前权能」。

## 五、信徒权能

- 新规则表 `rules.followerPowers`：七项小权能（一次性护盾、小布雨、掌心火、回春手、灵目、代神宣谕、小结界），各有最低神像阶段、价格、次数（0 表示常驻）。
- 弹窗第四个页签「信徒权能」：卡片底部选一个人（只列核心和狂热，选项写成「林小满（核心 · 1/2）」，满槽的置灰），付神力赐下去。核心带 2 项、狂热带 4 项。
- 次数型的同一项再赐一次是叠加次数，不占新槽；常驻的再赐一次会被拒。
- 赐予附带给 +5 信仰度，同样受每日上限。
- 信徒在正文里用这份力量时提交 `{"类型":"信徒用能","人物ID":"…","权能ID":"…"}`：次数减一，减到 0 就消失，常驻的不扣。
- 赐予下一轮正文会写她得到这份力量的那一下。

## 六、背包与供奉、化身所得

- 背包从商城里拿出来，成为己身页单独一块：等待生效、神力演化中、筛选（全部 / 商城 / 供奉 / 化身所得）、物品格子、「12 / 48 格」。
- **供品进背包**：布帛、银钱、金器、玉石、奇珍会作为供品放进去，标「供奉 · 王少钧」；烧掉吃掉的香烛、食供、心意不进。背包满了照常记神力，回执写「供品留在供桌上」，供奉事件不算失败。
- **化身所得**：USER 凝聚化身以后，正文里实际拿到东西时提交 `{"类型":"获得","名称":"麦芽糖","说明":"…","数量":2,"来自":"镇口糖摊"}`。名字和说明要过禁词（不能拿来刷神力、信徒、永久能力），一轮最多记 4 件。
- 丢弃要确认（红色按钮），整组一起删。

## 七、跨界货架

- 弹窗第二个页签，卖当前世界以外两个世界的货：三个世界各 16 件，按阶段筛，每个外界每天上 3 件，跟着剧情日换。
- 全程不调用模型，也不打开、不读取、不复制别的世界的世界书条目——清单是照「生成范围」一次写进规则表的。
- 状态栏上看得到来处（「界外 · 西幻」）；投影里只多一句「界外之物照效果写」，不告诉 AI 它来自哪个世界，免得剧透玉像后期的跨界。

## 八、群体觉醒

- 普通 ≥ 5 人的群体是候选，每轮按普通人数加权抽一个群体，几率 = 6% + 2% × 未出轮数，20 轮必出，距上次觉醒不满 12 楼不出，亲密和打斗不出，这一轮已经有来客或支线也不出。
- 骰子的种子是「聊天 + 用户楼层 + 觉醒」，注入和结算用同一句话算，重 roll 结果不变。
- 抓到人的方式：注入里写清群体、序号、该写什么资料块；AI 写出来的那个人由脚本改成核心、信仰度 60，群体和总数各挪一个。AI 自己也挪了人数不会重复挪。
- AI 没写出人就不清零，下次还出。

## 九、数据和兼容

- `重要人物` 多三个**可选**字段：`信仰度`、`当前权能`、`私密状态`。没到对应等级的人身上不会长出来（用 `z.preprocess` + `optional`，没有用会补默认值的包装器）。
- 新增顶层脚本字段 `信徒培养`（今日记录、待演升级、赐能待演、觉醒节奏）；`商城` 多 `演化`，背包条目多 `来源`、`来自`、`演化分钟`、`对象类型`，待生效条目多 `演化分钟`。
- `SystemEventSchema` 的类型加 `信仰`、`觉醒`、`信徒用能`、`获得`，另加 `事由`、`程度`、`权能ID`、`名称`、`说明`、`数量`、`来自`。
- 守卫：`scriptOwnedPaths` 加 `信徒培养`，`mutableFields` 加 `私密状态`；AI 写 `/重要人物/ID/信仰度`、`/当前权能` 时按脚本专属忽略，不会报成「固定人物资料」。
- **人物资料块写回不再冲掉活数据**：资料版本里删掉这三个字段，提交时保留变量里已经结算过的等级、信仰度、当前权能和私密状态。不然 AI 给老人物补一次资料，信仰度就没了。
- 迁移只做 `addMissing`：补 `信徒培养` 和 `商城.演化`；人物身上的信仰度靠结算兜底。
- 世界书：`[系统] 任务、积分、神像阶段、信徒与成人边界`（己身页、信徒差别、涩涩货架边界）、`[mvu_update] MVU 更新与输出格式`（信仰等级与信仰度分工、四种新事件、供品进包、群体人数由脚本挪）、`[系统] 不死、神力、跨界与人物关系`（小权能与大神赐的分工）、`[系统] 当前状态投影`（神力演化中、在场人物的信仰度/当前权能/私密状态、界外之物、背包只列 24 件）。

## 怎么测的

`F:\lkeke-build\tools\build.mjs` 先把 0.17.2 原样重建一遍验工具链，再出 0.19.0。规则表、投影里的 `gameRules` 副本、`EMBEDDED`、安装器两处源码仍由同一份源文件生成；`HUD_REVISION` 由构建脚本按内容重算（和 0.18.0 不同，老玩家的状态栏会换壳）。

纯 Node 断言 312 条，全部通过：

- `test/core.mjs`（44 条）：0.18 的供奉、支线、晋升演出、旧档兜底全部不回归。
- `test/schema.mjs`（29 条）：2.4.0 新档、四种新事件、信仰度三字段「没到等级就不长出来」、当前权能最多 4 项、2.3.0 迁移后旧字段一个不少。
- `test/bundle.mjs`（29 条）：六模块编译、引导脚本编译、manifest / runtimeSha256 / hudRevision / EMBEDDED 互校、注入顺序（晋升 → 信仰度 → 天命 → 来客 → 支线 → 觉醒）。
- `test/projection.mjs`（17 条）：用 ejs 真渲染，今日供奉、支线、神力演化中的剩余分钟、过期不显示、在场人物的信仰度/权能/私密状态、界外之物不泄地名、背包只列 24 件。
- `test/devotion.mjs`（53 条）：入信起点、查表加分与每日上限、脚本升级与人数迁移、玩家楼层不记账、狂热开放阶段、AI 越级拦截、私密状态门槛、旧档补值、事件去重与容错、资料块写回不冲掉活数据。
- `test/follower-powers.mjs`（22 条）：赐予门槛、槽位、次数叠加、扣费与账本不变式、用能次数、阶段不够。
- `test/awakening.mjs`（25 条）：骰子可复算、各种闸门、序号避开已具名成员、写出/没写出、AI 自己挪人数、越级新人被改回。
- `test/shop-lewd.mjs`（22 条）：开关、不进今日货架、使用时的对象要求、演化的建立/到期/收回/重 roll。
- `test/bag.mjs`（21 条）：供品进包与叠加、背包满时供奉照样入账、化身所得的四种拒绝、丢弃、守卫。
- `test/cross-shelf.mjs`（21 条）：只上界外两个世界的货、按天换、按阶段限、买进背包、清单自检（价格区间、字数、禁词、地名、来处）。
- `test/hud-shell.mjs`（29 条）：页签顺序与面板配对、三块真的搬走、弹窗与背包结构、六列页签与角标样式、hudRevision 自洽。

## 没测

- 信仰度、信徒权能、觉醒的手感没有调平，用的是计划书给的数。
- 跨界货品清单是照「生成范围」一次写死的，没有按世界再调。
- 多轮长跑的数值漂移（普通信徒一路涨到 100、连续觉醒）没有跑过。

## 注意

改动不在仓库里维护源码，全部靠仓库外的构建脚本生成。源码副本在 `F:\lkeke-build\src`，测试在 `F:\lkeke-build\test`。下次要在仓库里直接改文件之前，请先确认这个脚本还在。
