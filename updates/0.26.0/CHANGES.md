# 香火成神系统 0.26.0 改了什么

卡面 0.26.0，Schema 2.6.0（形状没动，老档直接可用）。这一版专治**开局第一回合人物资料空白**、**改聊天名后状态栏消失**和**「30 米」旧设定残留**。

## 一、开局第一位来客的资料终于真的写进去了（P0）

老版本开局时会写 `/重要人物/first_visitor`，但三处连环拦截让它落不了地：

1. **守卫丢包**：`state-patch-guard` 判断「没有 `<CharacterArchive>` 的新人物写入」一律忽略。开局提交时只发了变量补丁、没带资料块，于是这条人物写入被整条丢掉。
2. **额外模型解析覆盖**：开了 MVU「额外变量解析」的玩家，第 1 楼结束后变量会被第 0 楼的空白状态盖回去，`开局完成` 变回 `false`，结算与归档双双跳过。
3. **字段残缺**：模型偶尔把现场字段写成空串或「未记录」。

现在的链路：
- 开局提交时把模型输出的 `first_visitor` 资料与开局基准**双向融合**（空值/「未记录」不覆盖基准），再以完整 `<CharacterArchive>` + 变量补丁一起交给 MVU；解析完还会按补丁**再落一遍**，守卫怎么过滤都保证字段齐全。
- 正文里的资料块被重写成融合后的完整版本，`hud` 归档到世界书 `[人物固定资料]` 时拿到的是全字段。
- `clock`/`hud` 结算前若发现 `开局完成` 被冲掉，会按开局提交记录（`xhcs_opening_committed_v1`）当场补回，再继续结算与归档。
- 现场动态额外写进 `剧情/当前来客`；状态栏在还没有人物档案时直接用它兜底，不再显示满屏「未记录」。

## 二、改聊天名不再丢状态栏（P0）

旧逻辑用 `chatId` 哈希算世界书名，改名后算出的是另一本书：`reuse` 判定为「沿用」，于是既没建新书、又把聊天强行绑到一本不存在的书上，随后所有读写都报「世界书不存在」，状态栏直接消失。

现在：只要当前已绑定的是本系统建的 `香火更新_*` 且它确实存在，就直接沿用它（归档条目一条不丢）；绑定前还会检查目标书是否在列表里，不在就先建再绑；清理旧书时也绝不会删掉正在用的那本。

## 三、「30 米」旧设定彻底清空（P0）

双重领域（无敌 10 米 / 神力 100 米）早就是脚本口径，但 9 条官方世界书、地图地名摘要、祈愿池文案里还留着「初始神域 30 米 / 方圆三十米」。这一版全部改成双重领域表述，构建产物里 `/30\s*米|三十米/` 命中数为 **0**，模型不会再照着旧设定在正文里说「30 米」。

## 四、人物资料块解析失败的容错与提示（P1）

- `<CharacterArchive>` 改为三级降级解析：标准 JSON → 清洗 `align`/`style` 残留、中文引号、尾逗号、漏逗号后的 JSON → 字段级正则兜底。模型写脏了也照样能提取出人物。
- 实在修不好时不再静默丢弃：状态栏顶部出现琥珀色提示条，写明是哪一楼、什么原因，提供【查看原文】与【一键修复并重载】——本地清洗优先，修不动才调用模型修补，修完自动重新归档。

## 五、撤回道具时输入框里的指令一起清掉（P1）

点「使用」会往 `#send_textarea` 追加 `（使用道具：xxx，目标：yyy）`，旧版点「撤回」只退神力与背包，输入框里的指令还留着，下一轮正文照样演一遍。现在撤回会精准剥离这一条（用户自己打的字一个字都不动）。点「使用」也不再要求输入框为空——已有内容就换行追加。

## 六、界面与文案精修（P2）

- **窄屏瘦身**：360px 视口下顶部内边距、属性卡字号与副文案压缩为单行省略（`+5/日`、`普0 · 核0 · 狂0`、`10m/100m`），六个导航标签一行排、按钮 36px；<260px 才折两行。
- **己身页重排**：祈愿簿 → 背包 → 商城 → 肉身与神像（**默认折叠**，摘要栏显示「泥像期（未凝肉身） · 无敌 10米 / 神力 100米」）→ 神力账本。
- **地图页置顶**：地图 SVG 紧跟顶栏出现，神域速览条移到图下方，第一屏就能看到整张图。
- **触控热区**：背包筛选 40px、主题下拉 38px、数量步进 36/40px、神域入口与祈愿按钮 ≥40px。
- **祈愿文案**：「你应了了」改成 `已应允此愿（发送消息后生效，可撤回重选）`；祈愿人拆成「短称呼 + 身份/外貌副标」，输入框里的自动指令也只用短称呼。
- **首任务名统一**：首阶段任务按世界取 `初显威灵` / `古祠应声` / `古墩苏醒`，不再被一律改写成「初显威灵」。
