# 香火成神系统 0.18.0 改了什么

卡面 0.18.0，Schema 2.3.0。旧存档（2.2.0）在切换聊天时按固定的一条边迁移，只补默认值，不动余额、信徒和旧任务。

## 一、正文里的供品能换神力了

以前正文里 NPC 送来金银玉石，积分一分不涨。现在 NPC 真的把东西交到神像前时，AI 提交一条供奉事件，脚本按品类、成色、份数和供奉者的信仰算出来。

- **价格只在脚本里。** AI 只写「谁供了什么、几份、成色、求什么」，积分由脚本查表。和跪拜一样，AI 报多少不算数。
- **贵贱差得很开。** 玉石 30、金器 20、奇珍 80；香烛、食供 1 块；野花、清水只算心意，记 0 分，回执写「心意已收」。
- **份数会递减。** 前 5 份全额，6–20 份五折，超过 20 份两折，所以「十箱黄金」不会线性爆分。
- **信仰加成。** 同样一块玉，狂热信徒供是 ×2，路人供是 ×0.5。
- **有上限，跟着阶段长。** 石像期单次 30、每日 60；金像期单次 10000、每日 30000。超出部分不进账，回执写「已达上限」。
- **神不能给自己供奉。** 事件里的人名或人物 ID 等于神名、生前姓名时直接拒绝。
- **写错不连累别人。** 品类写错、份数写 0 或 999，只丢这一条事件并回一句提示，同一楼的其他事件照常结算，不会让整楼状态更新失败。
- **账本新增「供奉」分类。** 账本页多一行「今日供奉 x / 上限 y」、最近 3 条供奉记录，以及折叠起来的价目表。
- **带「所求」的供奉会留下一条还愿支线种子**，下一轮优先写成支线，奖励是本次实得的一半。

## 二、点晋升之后，下一轮正文真的会演

以前点完按钮只有一行系统提示，AI 经常一笔带过。

- 点确认时脚本记一条「待演晋升」（从哪阶到哪阶、新权能、新半径）。
- 下一次生成时，把晋升演出提示拼在所有注入的最前面：神像怎么变、天地什么异象、神格内在的感受、新权能是什么、在场人物各自的反应。五个目标阶段各写了一套素材，三个世界各加一句世界化的修饰。
- 结算（AI 楼层）之后清掉。玩家楼层、刷新页面、切聊天都不会清，重 roll 同一楼还能再演一次。
- 神格页在待演出期间显示「⏳ 待演出」，点完按钮还会弹一句「下次发言时正文会演出晋升场面」。
- 和「晋升线索」是两个不同的注入 id，同一轮都在时先演晋升，再出线索。

## 三、支线改成脚本掷骰，最多 3 条

以前支线完全靠 AI 自觉，上限 2 条还写死在五个地方，实际上基本不出现。

- 上限从 2 提到 3（Schema、脚本、世界书、状态投影、任务条一起改的）。
- 脚本每轮掷一次骰：基础 25%，每过一轮没出支线 +10%，距上次发布满 8 轮必出，刚完成一条支线的下一轮再 +15%。
- 骰子的种子固定为「聊天 + 用户楼层 + 支线」，重 roll 结果不变。
- 亲密或打斗的场面本轮不发，但保底计数继续累积。
- 已经有 3 条时直接不掷骰；AI 自己写了一条也清零保底。
- 任务条显示「x/3项」，没有支线时的文案改成会随剧情随机出现。

## 四、数据和兼容

- `收入分类` 多一项 `供奉`；`经济` 多 `供奉日期`、`今日供奉`、`供奉记录`（最多 20 条）。
- `神格` 多 `待演晋升`；`任务` 多 `支线节奏`、`支线种子`（最多 5 条）；`支线` 上限 3。
- 这些都是脚本专属字段，AI 的变量补丁写到会被忽略，不会把待演晋升删掉。
- 迁移只做 `addMissing`，补齐默认值；迁移后校验「旧字段一个不少、旧值一个不变」，这是更新引擎的硬要求，本地跑过。
- 旧存档即使没走迁移，进入结算时也会补齐这三组字段。

## 怎么测的

在仓库外写了一支构建脚本（`F:\lkeke-build\tools\build.mjs`），先把 0.17.2 原样重建一遍，确认三个文件的 sha256 和线上完全一致，再打补丁产出 0.18.0。规则表（`rules`）和状态投影里的副本、runtime 和第 3 个脚本里的 `EMBEDDED` 现在都由同一份源文件生成，不会再各写各的。

纯 Node 断言 102 条，全部通过：

- `test/core.mjs`（44 条）：供奉计价与上限、心意 0 分、神自供被拒、坏事件只丢自己、还愿种子、支线保底与场面抑制、晋升登记与清除、重 roll、旧档兜底、账本不变式。
- `test/schema.mjs`（24 条）：新档解析、供奉事件、支线截断、待演晋升、旧档 2.2.0 迁移后的字段保留检查。
- `test/bundle.mjs`（28 条）：六个模块编译、引导脚本编译、两份安装器源码一致、manifest / runtimeSha256 / hudRevision / EMBEDDED 互相对得上、acceptedScripts 同时收录新旧脚本哈希、注入顺序。
- `test/projection.mjs`（6 条）：状态投影用 ejs 真渲染，今日供奉行、三条支线、跨日归零都对。

## 没测

- 没有真酒馆环境，所以**没在 SillyTavern + 酒馆助手实机跑**：开局流程、流式/非流式、页面刷新、真实重 roll 都没截图。测试是纯脚本断言和模板渲染。
- HUD 新增的供奉卡片和「⏳ 待演出」标签只复用了现有样式类，没有实机看排版效果。
- 供奉的分值和各阶段上限按计划表原样落地，没有做手感调平。
- 支线保底是按注入时会用到的同一份状态推演的，真机上 AI 连写两条、AI 在满额时硬写第四条这类情况没见过实际表现（第四条会被 Schema 截掉）。

## 注意

改动不在仓库里维护源码，全部靠仓库外的构建脚本生成。源码副本在 `F:\lkeke-build\src`，测试在 `F:\lkeke-build\test`。下次要在仓库里直接改文件之前，请先确认这个脚本还在。
