# 香火成神系统 0.25.0 改了什么

卡面 0.25.0，Schema 2.6.0（形状没动，老档直接可用）。这一版专治**手机端卡在「正在初始化」**与**祈愿簿点了没反应**。

## 一、局域网 / 手机端「浏览器不支持升级锁」彻底根治

- **升级锁降级**：`navigator.locks`（Web Locks）只在安全上下文可用，`http://192.168.x.x`、HTTP 反向代理、部分手机 WebView 里它是 `undefined`。启动器与角色安装器都改成 `runWithLock(name, task)`：有原生锁就用原生锁，没有就用挂在宿主上的内存 Promise 互斥队列，**不再抛「浏览器不支持升级锁 / 浏览器缺少更新锁」**。
- **SHA-256 纯 JS 兜底**：同一批环境下 `crypto.subtle` 也是 `undefined`，修好锁之后立刻会在校验文件哈希时崩。启动器引擎、角色安装器、人物固定资料归档、HUD 档案处理签名四处全部改为 `sha256Hex()`：优先原生 `crypto.subtle.digest`，不存在时走内置纯 JS 实现，**输出与原生逐字节一致**（64 位小写十六进制）。
- `crypto.randomUUID` 同样只在安全上下文存在，安装器日志 ID 改用手写 UUID（有 `getRandomValues` 就用它，没有就用 `Math.random`）。

## 二、手机端不再卡死「正在初始化」

- **`currentFloor()` 不再抛错**：新增 `currentFloorSafe() / currentSafe()`，空聊天、切换聊天瞬间、第 0 楼还没挂载都返回 `null` 并静默跳过，**绝不抛「没有可读取的助手消息」**。
- **告警去重**：同一条提示 5 秒内只弹一次，`CHAT_CHANGED` 连续触发不再刷出 4 个橙色警告框。
- **第 0 楼死锁打破**：`opening.js` 的 `seedInitvar()` 要等 `startModules()`，而 `startModules()` 又在等 `stat_data.元数据.schema版本`。现在启动器在等待期间自己从内置 `[initvar]` 条目把关卡变量写进第 0 楼，两边都不用等对方。
- **非阻塞兜底**：等待从「30 秒后报错退出」改为最多 6 秒（40 × 150ms）；即便仍读不到（例如停在欢迎页），也**照常执行 `startModules()`**，开局定制向导与状态栏先渲染出来，真正开局后再补装存档。
- **网络防卡死**：远端 `version.json` 检查只抢 **2500ms**，抢不到就用内置包秒进、后台再补检查并缓存；`mvu_zod.js` 改为「testingcf 优先（4000ms）→ cdn 兜底」，全不可达只打一条轻提示，**开局界面照常渲染**。

## 三、祈愿簿：点了「应了」真的会有反应

- **致命清空 Bug 修复**：`transition` 里原来按「实例里的楼层」过滤 `祈愿簿.待生效`，玩家在第 10 楼点「应了」、第 11 楼一发消息就被清空，AI 根本没看到。现在只在 **AI 楼层结算（`aiSettlement`）** 时消费并发放回馈。
- **双通道祈愿，逻辑不再打架**：
  - 【信徒心香·远程可闻】（金色徽章）：`重要人物` 里已入信者（普通/核心/狂热或信仰度 ≥ 20）与 `信众群体` 会烧心香，**突破距离**向神明祈愿。
  - 【神力域内·XX 上香】（青色徽章）：非信徒必须走进当前神力领域覆盖范围（`domainCoverage` 的主庙及域内）上香才听得见——泥像期隔着几十里听到路人祈愿的割裂感没有了。
  - 池子仍按 `r <= 当前段位` 过滤，不会提前刷出远方高阶势力的祈愿。
- **点击即联动输入框**：`syncWishToInput()` 生成 `【祈愿簿·应了】回应XX的祈愿（渠道｜「前36字」）：`，输入框为空就填入、已有内容就换行追加，并触发 `input` 与聚焦。
- **`depth: 0` 必演强约束**：注入的祈愿簿指令改成「本轮正文必须明确写出显圣过程、祈愿人当场反应与结果，严禁忽略或一笔带过」。
- **香火与好感/信仰回馈**：应允发 `8 + 段位×4` 香火（泥像 +8 / 石像 +12 / 铜像 +16…，危机类祈愿再 +6），祈愿人若已建档则好感 +8、信徒再 +信仰度 +10（未入信且好感 ≥60 会提示可引导入信）；捉弄发 +4 香火，成年女性好感 +3、堕落 +5。卡片上直接显示「应允回馈：+N 香火 / 提升好感与信仰」。

## 四、开局首位来客第一回合资料完整

- `DATA.branchState[世界].visitorScene` 为三大世界各写一套开局现场：**当前服装 / 当前姿势 / 当前状态 / 当前心理 / 情绪 / 性格 / 外貌**，与开场正文严丝合缝。
- 开局补丁现在直接写 `/重要人物/first_visitor`（含 `所在位置`、`信仰等级:未信仰`、`好感度:20`、`堕落值:0`），不再等 AI 施舍。
- `buildOpeningContract` 升级：`<CharacterArchive>` 必须输出 `性格、当前服装、当前心理、当前姿势、当前状态、情绪`，并附上本世界现场基准与完整示例。
- AI 漏写或写成「未记录 / 未知 / 占位符」时，`mergeArchiveRecord()` 保留脚本写好的那份，不会再覆盖成「未记录」。
- `XhcsCharacterArchive.index()`（clock 与 hud 两份同步）补上 `所在位置`。
